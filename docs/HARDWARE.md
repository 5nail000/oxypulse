# Аппаратная часть OxyPulse

Единый справочник по проводке стенда. Константы в прошивке — [`firmware/src/config.h`](../firmware/src/config.h).

> API и JSON — [`API.md`](API.md) · прошивка — [`firmware/README.md`](../firmware/README.md) ·
> веб-UI — [`web/README.md`](../web/README.md)

## Контроллер

**ESP32 DevKit V1** (классический `esp32dev`, Type-C или micro-USB).

Общая **GND** у ESP32, всех датчиков, реле и сервы — обязательна. Без общей земли I²C и реле работают нестабильно.

## I²C — общая шина

| Сигнал | GPIO | В `config.h` |
|--------|------|--------------|
| **SDA** | **22** | `I2C_SDA_PIN` |
| **SCL** | **23** | `I2C_SCL_PIN` |
| Частота | **100 kHz** | `I2C_CLOCK_HZ` |

### Подтяжки

- **SDA** и **SCL** — два отдельных резистора (обычно **4.7 kΩ**) к **3.3 V**, **не к 5 V**.
- Логика шины — **3.3 V** (ESP32, ADS1115, DPS310, SCD41 breakout).
- SFM3300 питается от 5 V, но I²C совместим с подтяжкой к 3.3 V (HIGH ≥ 2.5 V по [даташиту SFM3300](https://sensirion.com/media/documents/8ECF0D28/62D13110/Sensirion_Datasheet_SFM3300-AW_SFM3300-D.pdf)).
- **Одна пара** pull-up на всю шину. На breakout (ADS1115, SCD41, DPS310) подтяжки часто уже есть — дополнительные на SFM3300 не нужны.

### Запрещено

| GPIO | Причина |
|------|---------|
| **34, 35** | input-only на `esp32dev`, SDA/SCL нельзя |
| **2, 15** | strapping pins — для I²C не рекомендуются |
| **22, 23** | заняты I²C — не использовать как GPIO через веб/API |

При старте прошивка сканирует шину и пишет найденные адреса в Serial. Отсутствующий модуль не блокирует остальные.

## ADS1115 + AO-02 (кислород)

| Параметр | Значение |
|----------|----------|
| I²C-адрес | **`0x48`** (ADDR → **GND**) |
| Канал | дифференциальный **A0 − A1**, усиление `GAIN_SIXTEEN` |
| Питание | 3.3 V |

### AO-02 → ADS1115

Вид с торца (три вывода):

```
  _______
1    2     3
```

| Вывод AO-02 | ADS1115 | Роль |
|-------------|---------|------|
| **1 + 2** (вместе) | **A1** | Vsensor− |
| **3** | **A0** | Vsensor+ |

Калибровка — [`firmware/README.md`](../firmware/README.md): `O2_OFFSET_MV`, `O2_AIR_MV`.

## SFM3300-250-D (поток)

На разъёме датчика: **SCK** = SCL, **DATA** = SDA.

| Pin | Имя | Подключение |
|-----|-----|-------------|
| 2 | VDD | **5 V** |
| 4 | GND | GND ESP32 |
| 3 | SCK | GPIO **23** (SCL) |
| 5 | DATA | GPIO **22** (SDA) |
| 1 | HEAT_GND | не подключать |
| 6 | HEAT | не подключать |

```
SFM3300          ESP32 / шина
──────────────────────────────
Pin 2  VDD   →   5 V
Pin 4  GND   →   GND
Pin 3  SCK  ──→ GPIO 23 (SCL)
Pin 5  DATA ──→ GPIO 22 (SDA)
         │              │
         └── 4.7 kΩ ────┴──→ 3.3 V  (если нет pull-up на других модулях)
```

**Важно:**

- Кабель **≤ 30 см**; при **> 10 см** — экранировать SDA/SCL (Sensirion).
- VDD **≥ 4.75 V**, иначе датчик сбрасывается.
- Pin 1/6 — нагреватель (~51 Ω); для сухого воздуха оставить отключёнными.
- Первое измерение после старта невалидно — прошивка учитывает.
- I²C-адрес **0x40**.

## Adafruit DPS310 (давление)

Breakout [Adafruit DPS310](https://learn.adafruit.com/adafruit-dps310-barometric-pressure-sensor) — только I²C. На плате **SDI** = SDA, **SCK** = SCL.

| Пин | Куда | Роль |
|-----|------|------|
| VIN | 3.3 V | Питание |
| GND | GND | |
| SDI | GPIO **22** | SDA |
| SCK | GPIO **23** | SCL |
| SDO | GND → **`0x76`** / 3.3 V → **`0x77`** | адрес I²C |
| CS | **не подключать** | иначе модуль уйдёт в SPI |

При daisy-chain **SCD41 → DPS310** по STEMMA QT DPS310 часто виден как **`0x77`**.

| Параметр | Значение |
|----------|----------|
| Адрес | **`0x62`** |
| I²C | SDA 22, SCL 23 |
| Питание | 3.3 V или 5 V (по модулю), I²C — 3.3 V логика |
| Обновление | раз в **5 с**; прогрев ~10 с после старта |

## STEMMA QT / Qwiic

4-pin кабель JST-SH (Adafruit / SparkFun):

| Провод | Сигнал | ESP32 DevKit |
|--------|--------|--------------|
| **Красный** | 3.3 V | 3.3 V (**не 5 V**) |
| **Чёрный** | GND | GND |
| **Жёлтый** | SCL | GPIO **23** |
| **Синий** | SDA | GPIO **22** |

Модули можно цепочкой (out → in), например **SCD41 → DPS310**. GND с ESP32 обязательна.

Цвета жгута у разных брендов могут отличаться — сверяйте по сигналам, не только по цвету.

## GPIO — реле и клапан

Whitelist в прошивке (`GPIO_WHITELIST`):

`13, 14, 16, 17, 18, 19, 21, 22, 23, 25, 26, 27, 32, 33`

### Типовая схема клапана

| Сигнал | GPIO | Логика |
|--------|------|--------|
| Реле IN | **26** | HIGH = клапан открыт |
| Импульс (tap) | **26** | HIGH 3 с → LOW (через веб/API) |

**Исполнитель:** электромагнитный клапан 2V025-08 **12 V** + релейный модуль **5 V** (логика реле от GPIO 3.3 V — проверьте совместимость модуля; при необходимости транзистор/оптрон).

## Servo (тест)

| Сигнал | Подключение |
|--------|-------------|
| PWM | GPIO **18** (или другой из whitelist) |
| VCC | **отдельный блок 5 V**, не с 3.3 V ESP32 |
| GND | общая с ESP32 |

Параметры PWM в `config.h`: 50 Hz, импульс 0.5–2.5 ms, угол 0–180°.

## Питание

| Линия | Назначение |
|-------|------------|
| ESP32 USB / VIN | контроллер (5 V на VIN → встроенный LDO 3.3 V) |
| **3.3 V** | ESP32, ADS1115, DPS310, логика I²C |
| **5 V** | SFM3300, SCD41 (по модулю), реле, servo |
| **12 V** | клапан (через реле, отдельный адаптер) |
| **GND** | общая точка для всех модулей |

Рекомендуется сетевой адаптер **12 V** + стабилизаторы **5 V** и **3.3 V** (или качественный USB-блок для ESP32 + отдельный 5 V для нагрузки).

## BLE — внешние датчики

ESP32 работает как **BLE central**: сам сканирует, подключается и отдаёт данные в `/api/status`. Телефон/браузер к этим устройствам **не подключается**.

### Wellue Ring O2 S

| Параметр | Значение |
|----------|----------|
| Протокол | OxyII custom GATT |
| Service UUID | `e8fb0001-a14b-98f9-831b-4e2941d01248` |
| Данные | SpO₂, HR, батарея, контакт, motion |
| Режим | **S8-AW** (live). В записи `T8520_xxxx` OxyII часто недоступен |

### COOSPO H6M (и аналоги)

| Параметр | Значение |
|----------|----------|
| Протокол | Bluetooth SIG Heart Rate |
| Service | `0x180D` |
| Characteristic | `0x2A37` (Measurement) |
| Данные | ЧСС (bpm), R-R интервал — если ремень отдаёт |

Автопоиск и reconnect при старте ESP32. Одновременно с WiFi нужен **modem sleep** — см. [`firmware/README.md`](../firmware/README.md).

## Диагностика

1. **Serial 115200** после прошивки — I²C-скан, статус каждого датчика.
2. Отсутствующий I²C-адрес → питание и pull-up, не код.
3. SFM3300 «молчит» → проверить **5 V ≥ 4.75 V**, длину и экран кабеля.
4. DPS310 не виден → SDO (0x76 vs 0x77), **CS не подключён**.
5. Wellue «поиск…» → режим S8-AW, кольцо заряжено, в зоне BLE ESP32.
6. COOSPO «нет данных» → ремень на теле, contact=true в JSON.

Пошаговые сценарии — [`TESTING.md`](../TESTING.md).
