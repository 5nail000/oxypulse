## UART-мост (BLE-узел ↔ главный DevKit)

921600 8N1, NDJSON (один JSON на строку). RX0/TX0 на DevKit **не использовать** — это CH340 (прошивка и монитор).

Прямая коммутация одноимённых пинов (на обеих платах BLE: **TX=GPIO16, RX=GPIO17**; на main: **RX=GPIO16, TX=GPIO17**):

```
BLE-узел (S3 или вторая DevKit)     ESP32-DEVKIT CH340 (главный)
GPIO16  TX  ───────────────────  GPIO16  RX   (Serial2)
GPIO17  RX  ───────────────────  GPIO17  TX   (Serial2)
GND         ───────────────────  GND
```

На S3-N16R8 не трогать: **19/20** (USB), **26–37** (octal flash/PSRAM), **43/44** (UART0).
На второй DevKit не трогать **GPIO1/3** (CH340).

Протокол (BLE → main): `hello`, `wellue`, `coospo` (~1 Гц), `rr` (каждый интервал). Обратный канал в v1 не нужен.

## I²C — две шины

На ESP32 DevKit V1 (**WROOM-32**) GPIO **20 нет**. Рабочий контур: **SDA=18 / SCL=19**.

| Шина | Роль | SDA | SCL | Частота |
|------|------|-----|-----|---------|
| **Hypoxia** | буферы **гипоксии и гипероксии**: O₂ + давление на каждом | **22** | **23** | 100 kHz |
| **Working** | рабочий контур: O₂, давление, поток, CO₂ | **18** | **19** | 100 kHz |

На шине **Hypoxia** висят датчики **обоих** буферов с **разными I²C-адресами** (например ADS1115 гипоксии `0x48`, гипероксии `0x49` при ADDR→VCC; DPS310 — `0x76`/`0x77` и второй модуль с противоположным SDO).

На каждой шине **свои** pull-up 4.7 kΩ к 3.3 V (или уже есть на breakout этой шины). Общая GND обязательна.

Адреса на **разных** шинах **могут совпадать** (оба ADS1115 рабочий/гипоксия = `0x48`). На **одной** шине адреса должны быть уникальны.

### Запрещено как GPIO, пока занято I²C

| GPIO | Причина |
|------|---------|
| **34, 35** | input-only, SDA/SCL нельзя |
| **2, 15** | strapping pins |
| **22, 23** | шина гипоксии |
| **18, 19** | шина рабочего контура |
| **16, 17** | UART-мост к BLE-узлу |

### Подтяжки

- **SDA** и **SCL** — два отдельных резистора (обычно **4.7 kΩ**) к **3.3 V**, **не к 5 V**.
- Логика шины — **3.3 V** (ESP32, ADS1115, DPS310, SCD41 breakout).
- SFM3300 питается от 5 V, но I²C совместим с подтяжкой к 3.3 V (HIGH ≥ 2.5 V по [даташиту SFM3300](https://sensirion.com/media/documents/8ECF0D28/62D13110/Sensirion_Datasheet_SFM3300-AW_SFM3300-D.pdf)).
- **Одна пара** pull-up на **каждую** шину. На breakout (ADS1115, SCD41, DPS310) подтяжки часто уже есть — дополнительные на SFM3300 не нужны.

При старте прошивка сканирует **обе** шины и пишет найденные адреса в Serial. Отсутствующий модуль не блокирует остальные.

## SFM3300-250-D (поток, **рабочий контур**)

На разъёме датчика: **SCK** = SCL, **DATA** = SDA. Шина **Working**: SDA=**18**, SCL=**19**.

| Pin | Имя | Подключение |
|-----|-----|-------------|
| 2 | VDD | **5 V** |
| 4 | GND | GND ESP32 |
| 3 | SCK | GPIO **19** (SCL) |
| 5 | DATA | GPIO **18** (SDA) |
| 1 | HEAT_GND | не подключать |
| 6 | HEAT | не подключать |

```
SFM3300          ESP32 / шина
──────────────────────────────
Pin 2  VDD   →   5 V
Pin 4  GND   →   GND
Pin 3  SCK  ──→ GPIO 19 (SCL)
Pin 5  DATA ──→ GPIO 18 (SDA)
         │              │
         └── 4.7 kΩ ────┴──→ 3.3 V  (если нет pull-up на других модулях)
```

**Важно:**

- Кабель **≤ 30 см**; при **> 10 см** — экранировать SDA/SCL (Sensirion).
- VDD **≥ 4.75 V**, иначе датчик сбрасывается.
- Pin 1/6 — нагреватель (~51 Ω); для сухого воздуха оставить отключёнными.
- Первое измерение после старта невалидно — прошивка учитывает.
- I²C-адрес **0x40**.

## Adafruit DPS310 (давление)

Breakout [Adafruit DPS310](https://learn.adafruit.com/adafruit-dps310-barometric-pressure-sensor) — только I²C. На плате **SDI** = SDA, **SCK** = SCL.

| Пин | Куда | Роль |
|-----|------|------|
| VIN | 3.3 V | Питание |
| GND | GND | |
| SDI | GPIO **22** (гипоксия) или **18** (рабочий) | SDA |
| SCK | GPIO **23** (гипоксия) или **19** (рабочий) | SCL |
| SDO | GND → **`0x76`** / 3.3 V → **`0x77`** | адрес I²C |
| CS | **не подключать** | иначе модуль уйдёт в SPI |

При daisy-chain **SCD41 → DPS310** по STEMMA QT DPS310 часто виден как **`0x77`**.

## Пневматика — клапаны, серво, концентратор

Whitelist в прошивке (`GPIO_WHITELIST`):

`4, 13, 14, 18, 19, 21, 22, 23, 25, 26, 27, 32, 33` (pin **4** — только Servo1, не `gpio_set`)

Не используй **18, 19, 22, 23** как обычные GPIO, пока на них I²C. **16/17** — UART, в whitelist нет.

**Исполнитель:** двухходовой электромагнитный клапан **2V025-08**, **12 V**, через релейный модуль **5 V**.  
**Логика реле: active HIGH** — HIGH на GPIO = реле ON = клапан **открыт** (альтернативный путь).  
**NC (без питания):** клапан **закрыт** — поток по пути «по умолчанию» (внешняя среда).

### Распиновка

| ID | Имя | GPIO | NC (OFF) | ON (HIGH) |
|----|-----|------|----------|-----------|
| **V1** | `IN_HYPO` | **25** | Вход с **внешней среды** | Вход из буфера **гипоксии** |
| **V2** | `IN_HYPER` | **26** | Вход с **внешней среды** | Вход из буфера **гипероксии** |
| **V3** | `IN_WORK` | **27** | Вход с **внешней среды** | Вход из **рабочего контура** (продув/осушка) |
| **V4** | `OUT_DEP_HYPO` | **13** | Обеднённый → **наружу** | Обеднённый → буфер **гипоксии** |
| **V5** | `OUT_DEP_HYPER` | **14** | Обеднённый → **наружу** | Обеднённый → буфер **гипероксии** |
| **V6** | `OUT_RICH_HYPER` | **21** | Обогащённый → **наружу** | Обогащённый → буфер **гипероксии** |
| **O2_MOTOR** | мотор концентратора | **33** | OFF | HIGH = мотор **включён** |
| **Servo1** | гипоксия / гипероксия | **4** (D4) | PWM 50 Hz | угол 0–180° (`servo_set`) |

### Логика входа (V1–V3)

| V1 | V2 | V3 | Источник воздуха |
|----|----|----|------------------|
| OFF | OFF | OFF | **Внешняя среда** |
| ON | OFF | OFF | Буфер **гипоксии** |
| OFF | ON | OFF | Буфер **гипероксии** |
| OFF | OFF | ON | **Рабочий контур** |

**Прошивка:** штатно активен **не более одного** из V1–V3. При одновременном включении нескольких — **запись в лог (warning)**, работа **не прерывается**: фактический поток определяется **приоритетом, заложенным при монтаже** (параллельные открытые клапаны на общем коллекторе).

### Логика выхода обеднённого (V4–V5)

| V4 | V5 | Куда уходит обеднённый воздух |
|----|----|-------------------------------|
| OFF | OFF | **Внешняя среда** |
| ON | OFF | Буфер **гипоксии** |
| OFF | ON | Буфер **гипероксии** |

**Прошивка:** при включении V4 **выключать** V5 и наоборот (взаимоисключение в софте). Если оба всё же открыты физически — **гипоксия перехватывает поток** (монтаж); в норме второй клапан не держится включённым зря.

### Логика выхода обогащённого (V6)

| V6 | Куда уходит обогащённый воздух |
|----|--------------------------------|
| OFF | **Внешняя среда** |
| ON | Буфер **гипероксии** |

V6 **независим** от V4/V5.

### Концентратор O₂

**O2_MOTOR** (GPIO **33**, active HIGH): реле/контактор **мотора концентратора кислорода**. Включение/выключение — командами прошивки или UI; буферы **наполняются или опустошаются** в зависимости от конфигурации клапанов и режима. Детали FSM — в прошивке и [`PROJECT_CONTEXT.md`](../PROJECT_CONTEXT.md).

**Расходы на текущем стенде** (номинал при работающем моторе, ориентир для расчёта наполнения буферов и ИГТ):

| Поток | л/мин | Куда в контуре |
|-------|-------|----------------|
| **Вход (забор / поглощение)** | **18** | Воздух с атмосферы через концентратор |
| **Выход обеднённый** | **16** | Линия V4/V5 → буфер гипоксии или наружу |
| **Выход концентрированного O₂** | **0,9** | Обогащённая фракция (V6 / буфер гипероксии — по монтажу) |

Сумма выходов (~16,9 л/мин) меньше входа (~18 л/мин) — остаток на утечки, продув и погрешность замера; при калибровке таймеров наполнения ориентируйтесь на **16 л/мин** обеднённого в буфер гипоксии.

### Поведение при сбоях

- **Старт / reset ESP32:** все GPIO клапанов и мотора → LOW (NC, безопасное «наружу»).
- **Потеря WiFi / обрыв связи с UI:** клапаны **не сбрасываются автоматически** — текущее состояние сохраняется до явной команды или перезагрузки.

## Servo1 — переключение гипоксия / гипероксия

| Сигнал | Подключение |
|--------|-------------|
| PWM | **D4** = GPIO **4** |
| VCC | **отдельный блок 5 V**, не с 3.3 V ESP32 |
| GND | общая с ESP32 |

На ESP32 DevKit CH340 метка **D4** соответствует **GPIO 4** (не путать с D18/D19 = GPIO 18/19).

Параметры PWM в `config.h`: 50 Hz, импульс 0.5–2.5 ms, угол 0–180°. Управление — `servo_set` / `servo_auto` в API (`pin`: **4**).

**ИГТ:** 180° — контур гипоксии (`IGT_SERVO_HYPOXIA_DEG`), 0° — нормоксия (`IGT_SERVO_NORMOXIA_DEG`). После последней нормоксии и при abort серва остаётся на 0°.

## Питание

| Линия | Назначение |
|-------|------------|
| ESP32 USB / VIN | контроллер (5 V на VIN → встроенный LDO 3.3 V) |
| **3.3 V** | ESP32, ADS1115, DPS310, логика I²C |
| **5 V** | SFM3300, SCD41 (по модулю), реле, servo |
| **12 V** | клапан (через реле, отдельный адаптер) |
| **GND** | общая точка для всех модулей |

Рекомендуется сетевой адаптер **12 V** + стабилизаторы **5 V** и **3.3 V** (или качественный USB-блок для ESP32 + отдельный 5 V для нагрузки).

## BLE — внешние датчики

**BLE-узел** (`firmwares/firmware_ble_s3` или `firmware_ble_devkit`) работает как **BLE central**: сам сканирует, подключается и шлёт снимки на главный узел по UART. Телефон/браузер к кольцу и ремню **не подключается**. Главный узел BLE не поднимает.

### Wellue Ring O2 S

| Параметр | Значение |
|----------|----------|
| Протокол | OxyII custom GATT |
| Service UUID | `e8fb0001-a14b-98f9-831b-4e2941d01248` |
| Данные | SpO₂, HR, батарея, контакт, motion |
| Режим | **S8-AW** (live). В записи `T8520_xxxx` OxyII часто недоступен |

### COOSPO H6M (и аналоги)

| Параметр | Значение |
|----------|----------|
| Протокол | Bluetooth SIG Heart Rate |
| Service | `0x180D` |
| Characteristic | `0x2A37` (Measurement) |
| Данные | ЧСС (bpm), R-R интервал — если ремень отдаёт |

Автопоиск и reconnect при старте BLE-узла. WiFi на S3 выключен — coexistence нет.

## Диагностика

1. **Serial 115200** главного узла — I²C-скан; `UART bridge: hello` когда BLE-узел на связи. `sensors.bridge.ok` в `/api/status`.
2. Отсутствующий I²C-адрес → питание и pull-up, не код.
3. SFM3300 «молчит» → проверить **5 V ≥ 4.75 V**, длину и экран кабеля.
4. DPS310 не виден → SDO (0x76 vs 0x77), **CS не подключён**.
5. Wellue «поиск…» → режим S8-AW, кольцо заряжено, в зоне BLE ESP32.
6. COOSPO «нет данных» → ремень на теле, contact=true в JSON.

Пошаговые сценарии — [`TESTING.md`](../TESTING.md).
